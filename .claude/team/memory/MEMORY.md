# Team memory — Network Management System

Curated index. One line per learning; detail in `learnings/`. Jarvis is the only writer.

- 2026-08-09 — **Stack is Node/TypeScript, never Java.** `/init-team` seeded a Java/Maven toolchain by default; the real project is React/Next.js + Node BFF with LibreNMS (PHP) as an unmodified engine. team-config §7 and all four overlays were corrected at G1. If any agent proposes Maven/`mvn`/`src/main/java`, it is reading a retired fact — stop and re-read team-config.
- 2026-08-09 — **The architecture reference contains two security anti-patterns; do not implement them as written.** Its Nginx sample injects a *global* LibreNMS API token into a browser-reachable `/api/v0/` proxy, and it suggests the browser query InfluxDB directly. Both are formally rejected in ADR 0002 and replaced by a server-side BFF (FR-08/FR-46/NFR-09, CON-6). Treat the reference as an architectural sketch to be reviewed, not a spec to be transcribed.
- 2026-08-09 — **LibreNMS core is never modified** (FR-07, goal G-6). Any design needing a core patch is a design failure — escalate instead, because core patches turn every LibreNMS security release into a merge exercise.
- 2026-08-09 — **Simulator-based verification has a trap: a simulator that always answers cannot test the "metric unavailable" path.** FR-24/FR-52 require the harness to withhold OIDs on demand, because rendering an absent RSSI as `0` on an RF dashboard is indistinguishable from a dead link.
- 2026-08-09 — **TR-069 is not a LibreNMS protocol.** It entered scope via the test-environment decision, not the architecture doc. LibreNMS is SNMP-centric; TR-069/CWMP implies a separate ACS. Architect recommends simulator-tolerance only (ADR 0004); real TR-069 monitoring would be a separate work item with its own G1, and TR-069 *writes* would collide with OOS-2 (no config management).
- 2026-08-09 — **Prefer structural enforcement over reviewer vigilance.** The strongest design choices here make requirements impossible to violate rather than merely forbidden: a `lint:deps` script failing CI if `web` imports `bff` (NFR-09/AC-F#31), a BFF-mediated opaque Redis session so no token can reach the browser (FR-12), and a `MetricValue` discriminated union whose absent case has no numeric slot (FR-24). Reach for this pattern first.
- 2026-08-09 — **A resolved open question can enlarge scope, not just settle a value.** OQ-22 looked like "which URL?" and turned into a systems-administration work package (FR-54..58) once the human confirmed LibreNMS must be installed on their server. Re-check scope whenever an answer lands, and re-issue affected FRs rather than absorbing the work silently.
- 2026-08-09 — **Verification "by design" is not verification.** ASM-1 (LibreNMS API covers every FR) was confirmed by reading docs, not by calling a live API. The plan therefore carries a dedicated real-API verification task, and its riskiest rows are server-side pagination (FR-38), filters (FR-31/37), and acknowledger identity (FR-32). Watch for agents treating a documented API as a verified one.
- 2026-08-09 — **Watch latency requirements worded against the wrong event.** NFR-05 says ≤10 s from LibreNMS *recording* a change, which is very different from the change *occurring* when polling every 5 minutes. Ambiguity of this kind silently converts an unachievable target into an achievable one (or vice versa) — pin the reference event.
- 2026-08-09 — **A security guard that can fail OPEN is worse than no guard, because it is trusted.** The `lint:deps` control enforcing "web never imports bff" (NFR-09/AC-F#31) skipped its source scan entirely when a package manifest was missing or malformed — so a real violation passed with exit 0. Found by the Developer during Task 1, fixed with regression tests on real temp-dir fixtures. Rule: every structural guard needs a NEGATIVE probe proving it fails when it should; exit 0 from an unproven guard means nothing. Re-probe `scripts/check-workspace-deps.mjs` after any change.
- 2026-08-09 — **`npm run lint` is currently a no-op** (`--if-present`, no workspace defines `lint`, ESLint never scaffolded — the plan named the script without the dependency). It exits 0 and proves nothing. Never cite it as a passing lint gate until ESLint is actually scaffolded.
- 2026-08-09 — **Plan-specified commands can be wrong in ways only execution reveals:** `tsc -b --noEmit` is invalid with composite project references (TS6310), and `node --experimental-strip-types` cannot resolve NodeNext `.js` specifiers. Both were in the approved plan and both failed on first run. Approved plans are not verified plans — expect the maker to hit and report this class of defect, and reconcile the plan text afterwards.
- 2026-08-09 — **Closing a fail-open instance is not closing the class.** The `lint:deps` guard was fixed for missing/malformed manifests, then failed open three more ways at G2.5 review: it only walked `packages/<pkg>/src` (blind to Next.js `app/`, `pages/`, package-root files), its extension allowlist missed `.jsx/.cts/.cjs`, and its import regex missed dynamic `import()` and side-effect imports. Root cause: it reasoned about *text in a subdirectory* instead of *the module graph*. Lesson: when a guard fails open once, ask what CLASS of input it mis-handles and fix the abstraction (AST parse), not the symptom (another regex).
- 2026-08-09 — **Placing a crash on the failure path doubles its cost.** `redact()` stack-overflowed on circular objects and was reachable from the error handler, so a handled error became a process crash AND destroyed the log explaining it. Audit failure-path code (error handlers, loggers, health checks) more harshly than happy-path code.
- 2026-08-09 — **Anything that cannot fail is not a check.** Hardcoded always-OK health placeholders and a no-op `npm run lint` both report success while proving nothing — the same defect class as the fail-open guard. Unimplemented checks must fail CLOSED or be explicitly absent; never fabricate OK.
- 2026-08-09 — **Jarvis's copy of an agent report can be lost (0-byte transcript) even when the report itself survived elsewhere.** At G2.5 the reviewer's 19 findings reached the team intact but Jarvis's transcript copy was empty, so Jarvis relayed a degraded reconstruction and told the Developer to "re-derive" 7 items that were in fact fully specified. Two mitigations: (a) verifier roles MUST write findings to `.claude/team/artifacts/<work-item>/` as a file rather than relying on the returned message; (b) when a report looks truncated, say so and re-verify independently before relaying — Jarvis reproduced the 3 Criticals by live probe, which is why those survived the loss intact. Never present a reconstruction as verbatim.
- 2026-08-09 — **`typescript@7` is the native Go rewrite and exposes NO JavaScript parse API** (`ts.createSourceFile` is gone). Any plan step that assumes "typescript is already installed, so AST work is free" is invalid on TS7. Use `@babel/parser` (commonly already in the lockfile via vitest) or another parser, declared and pinned explicitly.
- 2026-08-09 — **A guard must be measured on BOTH axes.** The rebuilt dependency guard was verified with 9 violation forms that must fail (outside `src/`, `.jsx`, dynamic `import()`, side-effect, deep specifier, `require()`, re-export, type-only, `lib/`) AND 2 import-like-text cases that must pass (comment, string). False negatives let violations through; false positives get the guard socially bypassed. Test both directions or the control is unproven.
- 2026-08-09 — **The maker found the original defect was worse than the reviewer reported** (7 of 10 probes escaped, not 3) and found an extra unreported one: `ROLE_MAP` — authorization config — accepted `123`, `[1,2]`, and `null` before shape validation was added (`env.ts:84-91`). Encourage makers to report severity ESCALATIONS; a fix round is the cheapest moment to find siblings of the same defect class.
- 2026-08-09 — **Test the AXIS, not more values on the same axis.** The dependency guard's third fail-open (finding 20) survived 64 tests and 11 Jarvis probes because every one used a **string-literal** specifier. Template literals, `BinaryExpression`, and `Identifier` specifiers were never exercised — a whole node-type axis untested while the value axis was saturated. When a control has an input taxonomy (node types, encodings, protocols), enumerate the taxonomy; adding a 12th value on the axis you already cover proves nothing new.
- 2026-08-09 — **Check code against the safety invariant it declares in its own comments.** `scripts/check-workspace-deps.mjs:28-30` states "every error path here must produce a VIOLATION, never a silent skip" — and `pushString` plus two `walk()` catch blocks did exactly that silent skip. The comment was right; the code disagreed. A stated invariant is a free test oracle: grep for it, then verify every error path honours it.
- 2026-08-09 — **When one fail-open is found, assume siblings until proven otherwise.** This single file yielded three sequential fail-opens (manifest parse → subdirectory/extension/import-form → non-literal specifier), each surfacing only after the prior fix. Budget for a class sweep of every error path in the file, not a point fix; and have the maker report unasked-for siblings.
- 2026-08-09 — **Fail-closed beats enumerate-and-catch.** The dependency guard's four fail-opens all came from enumerating *allowed* shapes and silently ignoring the rest. The durable fix inverted the default: classify every specifier as `resolved | unresolvable`, and treat unresolvable as a VIOLATION. Scope it (rule-carrying packages only) so it is not blanket-noise — `bff` may use dynamic imports, `web` may not — and emit a message naming the node type so the failure is actionable. Prefer this shape for any allowlist-style control.
- 2026-08-09 — **Mutation testing is the cheap proof that tests are not vacuous.** Claim: "the tests cover the fail-closed branch." Verification: disable the branch and confirm the suite fails — 10 of 99 guard tests died. A passing suite proves nothing about a branch until you have watched the suite fail without it. Also note the maker did this unprompted, and Jarvis reproduced it independently.
- 2026-08-09 — **A representational gap can be the root cause.** `extractSpecifiers` returned `string[]`, a type that literally cannot express "a specifier I could not resolve" — so the only options were a fake string or silence, and silence won. Widening the type to `{kind, value|nodeType}[]` made the failure case representable and therefore handleable. When a control keeps failing open, check whether its data types can even express failure.
- 2026-08-09 — **Windows blocks symlink creation, which silently disables symlink tests.** Instead of skipping (0 coverage while looking green), inject a `readDir` seam so both branches execute on any OS. A skipped test is an untested path wearing a passing badge; verify `skipped: 0`, not just `fail: 0`.
- 2026-08-09 — **Distinguish a finding from an observation.** At iteration 3 the reviewer found transitive laundering (unruled package imports `bff`, re-exported into `web`) and recorded it as an OBSERVATION, not a finding: it is inherent to the direct-edge rule model, pre-existing, and a design decision rather than a defect. That judgement kept the loop closable while still capturing the risk (reconciliation item 10). Reviewers who cannot make this distinction either block forever or lose real risks.
- 2026-08-09 — **A `default:` branch is where fail-open hides.** The reviewer's exit criterion at iteration 3 was proving the guard's `default:` case declines classification while recursion continues, so no third outcome is possible. When auditing an allowlist-style control, enumerate its outcomes and prove there is no unhandled path — 4 mutants killed (19/1/2/1 test failures) is what "proven" looked like here.
- 2026-08-09 — **G2.5 review loop closed at 3 iterations: 20 findings + 1 maker-found (ROLE_MAP), final head `b0cd4b9`, 222 tests / 0 skipped.** Four sequential fail-opens in ONE security-relevant file (`scripts/check-workspace-deps.mjs`), each surfacing only after the previous fix. Budget review effort accordingly for structural guards: they attract this defect class because their happy path always looks healthy.
- 2026-08-09 — **A missing completion report does not mean missing work — check the artifacts before re-dispatching.** The Architect's deployment amendment produced no report and was presumed lost; its output was fully on disk (plan Revision 3, ADRs 0005/0007/0008 revised). Re-dispatching would have duplicated hours of finished work and risked conflicting edits. Verify the deliverable's expected artifacts first; treat silence as a reporting failure, not necessarily a work failure.
- 2026-08-09 — **Reconnaissance that invalidates both planned options is the recon working, not failing.** Task 0.1 found `10.121.77.206` to be a shared host with no sudo, existing workloads (Kafka, ZooKeeper, Samba, ports 8077/5000), and SELinux Enforcing — so neither planned install branch (Docker Compose, native) fit. The human chose a THIRD shape: rootless Podman, unprivileged ports, home-dir storage, co-tenancy consent. Absorb such a change into the plan as a new documented branch BEFORE execution resumes; never improvise it at the terminal.
- 2026-08-09 — **Unprivileged ports silently change what a POC can prove.** Rootless containers cannot bind <1024, so traps move 162→1162 and syslog 514→1514. Our own simulators can be pointed anywhere, so tests pass — but **real devices cannot**, and FR-56 specifies the privileged ports. A deployment constraint quietly became a requirements conflict. Always ask which acceptance criteria a hosting constraint makes unverifiable, and route the requirement wording back to the human rather than editing an approved FR.
- 2026-08-09 — **Re-scoping a criterion must state what is NOT covered.** AC-F#35 was re-scoped from >5,000 devices to POC scale (tens). Recorded explicitly: NFR-01/NFR-02 remain requirements needing a dedicated host later, and are NOT satisfied by the POC. A silent re-scope would have let a scale requirement look verified by a test that never exercised it.
- 2026-08-09 — **Jarvis published a wrong test count by trusting a report instead of the command.** Docs said 222; the real figure was 231 — a bff-only vitest total plus the guard suite, silently omitting 9 `@nms/shared` tests. The Tester caught it at run-1. Rule for Jarvis: when recording a numeric baseline in team-config or an overlay, run the command and read the output; a number relayed through a summary is hearsay. Corollary: quote the breakdown (per-package + per-runner), because a bare total hides which suites were counted.
- 2026-08-09 — **Framework-level errors bypass an app's own error taxonomy.** `createErrorHandler` honoured `status` only for `AppError`, so body-parser's 413/400/415 client errors all surfaced as 500 INTERNAL_ERROR logged at ERROR — misattributing client faults to the server and polluting the alerting signal. When designing an error handler, enumerate the errors the *framework* throws (body parsers, routers, proxies), not just the ones the application defines.
- 2026-08-09 — **Rootless containers cannot preserve client source IPs by default** (Podman's `rootlessport`), and LibreNMS attributes traps and syslog **by source IP**. Every trap would arrive from the container gateway and be filed against no device, while ports look open and logs show receipt — presenting as "the simulators are broken". Requires `rootless_port_forwarder="pasta"`, verified empirically. Generalisation: verify identity-carrying network attributes end-to-end, not just reachability.
- 2026-08-09 — **`:Z` vs `:z` is not a style choice.** `:Z` is a private single-container SELinux label; a volume with multiple consumers (the LibreNMS RRD tree has three) must use `:z`. Following a "use :Z" instruction literally would have broken the stack — the Architect deviated deliberately and recorded why. Instructions about labels/permissions must be checked against the actual sharing topology.
- 2026-08-09 — **Allowlist beats "honour whatever status the error carries."** Mapping framework errors by an explicit `type` allowlist (body-parser's `entity.too.large` → 413 etc.) avoids two silent failures that generic status-honouring causes: an upstream client error carries the REMOTE server's status (a LibreNMS 404 becomes *our* 404), and a 5xx can be silently downgraded to 4xx and fall off the paging path. Unknown/new error types fall through to 500 — fail-closed by design, and that default must be documented so nobody "improves" it later.
- 2026-08-09 — **A surviving mutant means the test exercises the wrong axis.** During the error-boundary fix one of four mutants initially survived; the fix was to rewrite the test to target the actual decision, not to add another assertion. Treat a surviving mutant as a defect in the test's aim, not its quantity.
- 2026-08-09 — **4xx must not log at ERROR.** Client-caused failures (oversized body, malformed JSON, bad charset) logged at ERROR pollute the alerting signal and page humans for someone else's bad request. Map client faults to WARN/INFO and reserve ERROR for server faults — the log level is part of the error contract, not decoration.
- 2026-08-09 — **Object-literal lookup tables are prototype-reachable, and an `=== undefined` guard does NOT protect them.** `TABLE[userControlledKey]` with key `constructor`/`toString`/`__proto__`/`valueOf`/`hasOwnProperty` returns an inherited member, so the undefined check passes and the code proceeds with a function where it expected a config object — here `mapped.status` was `undefined`, `res.status(undefined)` threw, and Express's default handler leaked an HTML stack trace with absolute paths. Use `Object.create(null)`, a `Map`, or `Object.hasOwn` for ANY table keyed by external input. Verified: `Object.create(null)` closes all five probe keys.
- 2026-08-09 — **An error boundary that can itself throw is not a boundary.** The BFF's error handler had no `headersSent` check and no try/catch, so any fault inside it escaped to the framework default — converting a handled error into the exact stack-trace leak the handler exists to prevent. Every centralized error handler needs a double-fault guard with a minimal hardcoded safe response.
- 2026-08-09 — **Fifth fail-open of the same shape in this codebase** (4× dependency guard, 1× error handler), all in security-relevant boundary code, each found only after the previous was fixed. The recurring tell: a lookup/allowlist whose *miss* path is implicit. When reviewing such code, ask "what does an unexpected input do?" before "does the happy path work?", and probe the LOOKUP MECHANISM rather than more key values.
- 2026-08-09 — **Prefer the fix a future edit cannot silently undo.** For the prototype-reachable allowlist, `Object.create(null)` and `Map` both close the hole today — but the Developer chose `ReadonlyMap` because a later literal-rewrite or object spread would silently restore `Object.prototype`, whereas `Map` has no index syntax to misuse, so the regression becomes a COMPILE error rather than a silent fail-open. When two fixes are equally correct now, pick the one whose failure mode is loud.
- 2026-08-09 — **A safe fallback must contain nothing that can throw.** `writeMinimalFallback` uses a module-level pre-built JSON string (no serialization at fault time), assigns `res.statusCode` instead of calling `res.status()` (which threw in the original defect), checks `headersSent` before writing, and ends in `res.destroy()` — never `next(err)`, which would hand control back to the framework default it exists to avoid. Build fallbacks from constants, not computation.
- 2026-08-09 — **A fix can trade a visible failure for an invisible one.** The double-fault guard added for finding 4 correctly stopped the stack-trace leak, but wrote NO log — so with `logger.ts`'s bare `process.stdout.write` throwing on EPIPE (verified: `e.code === 'EPIPE'`), a genuine server fault produced a correct 500 to the client and NO record anywhere: ERROR rate flat during a real incident. Ask of every containment guard: "when this catches, who finds out?" A silent catch on a failure path is an observability defect even when the response is correct.
- 2026-08-09 — **Never let the ABSENCE of behaviour be a test's oracle.** `errorHandler.test.ts:364` asserted a guard worked by relying on "the fallback writes no log at all" — so the moment the fallback legitimately gained a log line, the test's premise became invalid. Oracles must assert the intended DECISION (status/json never called again, distinct message emitted), not an incidental silence that a future correct change will break.
- 2026-08-09 — **Probing a replacement container is part of verifying a prototype fix.** Run-3 tested `Map.prototype`'s own members (`get`, `set`, `has`) against the new `ReadonlyMap` lookup — the "swapped one prototype container for another" trap. When a fix changes data structure to escape a prototype hazard, probe the NEW structure's inherited surface too.
- 2026-08-09 — **JARVIS GATE ERROR: a relayed recommendation is not an approval.** Jarvis told the Developer that allowlisting `querystring.parse.rangeError` as 400 was "approved to proceed" and recorded it as a human decision. The human had never ruled on it — the chain was Developer recommends → Tester concurs → Jarvis concurs, which is three recommendations and zero approvals. Agreement among agents feels like consensus and reads like authorization; it is neither. **Only an explicit human answer routed through the coordinator counts as approval.** When writing "approved" into any doc, sign-off table, or dispatch, be able to point at the human's actual words. Default to "PENDING HUMAN RATIFICATION" — it costs nothing and is trivially upgraded.
- 2026-08-09 — **Contain a failing transport at its source, not at each caller.** `logger.ts`'s bare `process.stdout.write` turned every `logger.error(...)` into a throw into its caller on EPIPE, so a log failure became a second fault at whichever site was reporting the first. Fixing only the error boundary's fallback treated the symptom; the durable fix was stdout → stderr retry → deliberate documented silence inside the logger, so no caller can ever be broken by the log transport. Containment is only defensible when it is not silence — retry a different channel first.
- 2026-08-09 — **An uncompilable mutant is not a killed mutant.** The Developer discarded 3 invalid mutation runs (mutants that failed to compile or executed zero tests) and now validates compile+execution before counting a kill. Without that check, mutation scores silently inflate — the suite "killed" something that never ran. Verify the mutant is live before crediting the test.
- 2026-08-09 — **Watch for coupling that degrades silently rather than failing.** `prevalidatedRequestId` gates on a UUID regex; if the ID generator were swapped (e.g. to ULID), every fallback requestId would quietly become `"unknown"` with ZERO test failures — losing traceability exactly when it matters. A drift-guard test asserting the generator's output still matches the consumer's pattern is the cheap defence. Look for validator/generator pairs whose mismatch produces degradation instead of an error.
- 2026-08-09 — **Recon can report a STOP condition it never actually measured.** Task 0.1 flagged subuid/subgid as a blocker requiring root, but never captured `/etc/subuid` / `/etc/subgid` contents — and many EL9 installs pre-populate ranges, in which case there is no blocker at all. A blocker asserted from inference rather than observation can stall a project for days. Always check whether the STOP was measured or assumed before escalating it to the human.
- 2026-08-09 — **When a rollback safety net is waived, the remaining guardrail becomes load-bearing.** The human waived the pre-flight VM snapshot, so there is no restore point on a shared host carrying a third party's production Kafka. That elevates "stop before destruction" and "confine everything to `~/nms`" from good practice to the only protection that exists. Record the consequence of a waiver, not just the waiver.
- 2026-08-09 — **CONFIRMED: the subuid/subgid "blocker" was never real.** Measurement found `aqaillm:296608:65536` in both `/etc/subuid` and `/etc/subgid`, and `podman unshare id` mapping correctly — the account had already run rootless containers for weeks. Task 0.1 had escalated it to the human from inference, never having read the files. This cost a human round-trip to an admin that was never needed. **Never escalate an unmeasured STOP.** State plainly whether a blocker was observed or inferred.
- 2026-08-09 — **Two human guardrails can name the same path once a host fact lands.** "Store under `~/nms`" and "NEVER `/opt/airlinq`" were both correct when written — then `$HOME` turned out to be `/opt/airlinq/aqaillm`. The right move was to STOP and route the contradiction back, not to pick the convenient half. Corollary: `$HOME` is a host fact, not an assumption; capture it in recon.
- 2026-08-09 — **A disk guardrail must name the filesystem, not a path that looks like it.** Every "stop above 80%" check was written against `df -h /`, but all writes would land on `vg_opt-lv_opt` via `$HOME`, so `/` would sit unchanged at 29% however much was written and the abort could never fire. Bind resource guardrails to the device that will actually fill, and verify with `df` on the real target before trusting them.
- 2026-08-09 — **Sharing a UID with long-running services makes account-wide operations dangerous.** The deploy account also runs `cli/serve.py` (:8077) and `local_rag` (:5000), so the plan's teardown `loginctl disable-linger` would kill them, and any blanket `podman system prune` would destroy their images. When co-tenanting under one account, audit every account-scoped command (linger, prune, systemd --user reset) for third-party blast radius.
- 2026-08-09 — **Drift guard verified by Jarvis independently:** flipping `PREVALIDATED_UUID` to uppercase-only made 2 of the 3 new correlation-id tests fail, proving the guard detects real generator/validator divergence rather than passing vacuously. A guard nobody has watched fail is not a guard.
- 2026-08-09 — **A G2-approved assumption can be false and only prove it at deploy.** OQ-3 was answered "TimescaleDB" and ADR 0005 accepted it — but LibreNMS 25.7.0 has NO PostgreSQL/TimescaleDB datastore driver, so the hypertable sits at count=0 with nothing able to write to it. The gap was invisible through G1/G2/G2.5/G3 because none of those stages touched a running LibreNMS. Lesson: an integration assumption about a third-party product's capabilities is not verified until something actually connects the two ends; flag such assumptions as deploy-time risks in the design, not settled facts.
- 2026-08-09 — **`podman info` reporting `pasta` is not proof that pasta is in effect.** Source-IP preservation held only in the default pasta netns; a named bridge network uses netavark+rootlessport and masquerades the source. The recon inferred "pre-solved" from `podman info`; measurement showed `SRC=10.89.0.53` (container addr) and only `--network pasta` gave the real `172.16.10.22`. Config-present is not config-effective — prove network-identity properties with an end-to-end packet, per topology.
- 2026-08-09 — **POSITIVE: a maker exposed a secret to its own terminal, rotated it immediately, and self-reported (F-3).** An snmpd debug capture printed the generated SNMP community; it reached no file/commit, the agent rotated to a fresh 28-char value and reported the event rather than hiding it. This is the behaviour the credential-hygiene rule wants. Caution captured: avoid snmpd debug flags that echo secrets. Jarvis confirmed no community string appears in any artifact or manifest.
- 2026-08-09 — **Four latent deployment defects were found and fixed under execution** (fping needs CAP_NET_RAW; cross-UID RRD perms; nginx resolve-once causes 502 after a backend restart — fix proven durable; snmpd double-bind), and container log caps were proven by FILE SIZE not `podman inspect` (journald silently ignores max-size). Deployment verification must measure the artifact (file bytes, a real packet, a row count), never trust the inspect/info field.
