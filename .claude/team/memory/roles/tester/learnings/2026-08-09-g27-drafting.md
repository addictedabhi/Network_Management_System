# 2026-08-09 — Drafting the G2.7 list for nms-platform-foundation

**Context:** first G2.7 draft. Only plan Tasks 1-3 exist (shared + bff + deps guard). 37 acceptance criteria, 4 partially coverable.

**Learned:**
1. **Overlay/team-config facts can be stale against the branch head.** The overlay said `npm run lint` was a bare `--if-present` no-op and `npm run dev` was broken via `dev:web`/`sim`. At `b0cd4b9` `lint` chains `lint:deps` and `dev` = `dev:bff` with the broken scripts removed. Read the actual manifest before asserting a command's behaviour; draft the check rather than repeating the documented claim.
2. **The honest deliverable of an early G2.7 is the coverage BOUNDARY, not case count.** More value came from the 16-row not-implemented table and the AC map (4 partial / 31 deferred / 2 human-judged) than from any single case.
3. **Draft "assert the absence" cases where a control does not exist yet.** No session layer → assert NO `Set-Cookie` is emitted, rather than skipping cookie security or pretending to check attributes.
4. **A test count increase is a finding, not a bonus,** when the human approved a plan against an exact baseline (222).
5. **Pair every negative with its positive.** Redaction (L-01/L-02), circular vs DAG (L-06/L-07), unavailable vs a genuine zero (M-02/M-03), guard violation vs false positive (G-02/G-04).
6. **Documented limitations need a confirmation case, not a finding.** Transitive laundering exits 0 by design; drafting it as a limitation-boundary case preserves the risk record without reopening a closed Architect question.
7. **Split half-judged cases explicitly.** Message actionability: list what is mechanically checkable, then hand the "does it communicate" half to the human rather than faking an oracle.

**Do differently:** verify manifest/script facts against head before drafting; state the coverage boundary before the cases.
